# Main-Toolbar-Extended — Agent Instructions

## Authority and scope

This repository contains the **Main-Toolbar-Extended** 3ds Max toolbar. Follow the current shared MaxScript `AGENTS.md` and its applicable linked rules in the MaxScript agents folder before making code or UI changes. This project file adds repository-specific requirements; it does not replace shared instructions.

The designated Google Drive folder `Main-Toolbar-Extended` is the canonical repository. Read the current Drive copy of each file you intend to change. Update canonical files in place by their Drive IDs, preserve unrelated edits, and create a new numbered version file for each new code release. ## Core dependency

Reuse the existing shared `Toolbar-Creator.ms` public function `manageScriptToolbar` without copying or editing the shared implementation. The tool depends on Toolbar-Creator being evaluated in 3ds Max first. This repository is a downstream consumer, not the owner of Toolbar-Creator or any shared Functions/Operations/Tools/Toolsets layers. Treat shared layers as read-only unless the user explicitly authorizes a specific protected edit in the current prompt.

## Behavioural contract

Build one native dockable CUI toolbar with **27 actions** grouped into Transform Centers (3), Coordinate Systems (7), Axis Constraints (6), and Snap controls (11). Snap targets must be icon-only, with concise tooltips. Use native snap settings and `on isChecked do` macro callbacks for live state; do not substitute a custom stale state cache. Preserve distinct 2D, 2.5D, and 3D snap projection modes. Preserve Grid Points, Vertex, Pivot, Midpoint, Bounding Box, Center Face, and Angle Snap controls. Keep Pick Object as a reference coordinate system option.

**Known limitation:** The project's installer upgrades the `.mcr` generated by Toolbar-Creator. Treat this as a documented adapter requiring runtime validation; do not imply that Toolbar-Creator itself supports checked-state actions or icon-only semantics natively.

## Validation and release

- Follow shared syntax, protected-identifier, UI, and failure-handling rules. Use `function` and camelCase functions, snake_case variables, and `if ... then`, with opening blocks on a new line.
- Do not guess native MaxScript API names or snap item indices; verify APIs against the intended 3ds Max version and, where possible, test in a connected 3ds Max instance.
- Run focused static validation. Include executable test code and confirm the UI is working before calling a release runtime-tested.
- CUIX manipulation changes the user's interface. Always preserve backups and report failures without fake success.
- Keep canonical entry source and versioned release snapshots separate. Avoid duplicate or `copy`-suffixed Drive names.
- This initial 0.001 package has **not** been validated in a running 3ds Max session. Do not claim otherwise until it has been tested.
